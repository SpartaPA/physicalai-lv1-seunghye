## 1. 파이프라인 전체 구조

- 좌표계 체인 (base -> link -> camera -> object) 그림 또는 다이어그램: `base 좌표계를 기준으로 로링크(link)를 거쳐 카메라(camera)가 장착되어 있으며, 카메라 시점에서 감지한 물체의 상대 위치를 바탕으로 object 좌표계를 추정합니다.`
- 각 노트북·모듈이 맡는 역할 (01 파이프라인 / 02 보간 / 03 자세 추정·시연): `01 노트북은 기본 변환과 회전 표현을 다루며, 02 노트북은 쿼터니언 보간(SLERP)과 궤적 생성(스플라인)을, 03 노트북은 3D 점군 정합 및 최종 픽앤플레이스 애니메이션 시연을 담당합니다.`
- 데이터 흐름: 카메라 점군 -> `PosePipeline` -> base 점군 -> PCA/Kabsch -> 목표 자세 -> SLERP + 스플라인 -> 애니메이션: `카메라 좌표계에서 획득한 원시 점군 데이터를 파이프라인을 통해 전처리 및 노이즈 제거 후 base 좌표계로 변환하고, PCA 및 Kabsch 알고리즘으로 목표 자세를 추정합니다. 이후 SLERP와 큐빅 스플라인을 결합하여 위치와 자세가 동기화된 부드러운 궤적을 생성해 애니메이션으로 시각화합니다.`
- 모듈 ③ 에서 가져온 함수와 이번에 새로 만든 함수 구분: `모듈 3에서 구현한 쿼터니언 변환 및 SLERP 함수와 모듈 4에서 구현한 큐빅 스플라인(cubic_spline_interp), 5차 다항식(quintic_profile) 함수를 통합하여 사용했습니다.`

## 3. 노이즈·점 개수가 정확도에 미친 영향

- 노이즈 0 ~ 0.25 스윕에서 오차가 어떻게 커졌는가: `노이즈 표준편차가 증가할수록 점군의 기하학적 형상 변형이 커져 Kabsch 알고리즘의 회전 및 병진 오차가 비선형적으로 급증했습니다.`
- 점 개수 30 / 90 / 270 계열 비교 — 점이 많을수록 오차가 줄어드는 정도 (대략 몇 배): `점 개수가 30개에서 270개로 증가함에 따라 통계적 오차가 약 3배 이상 감소하여 정합 안정성이 크게 향상되었습니다.`
- 구형 점군에서 PCA 주축이 불안정해진 이유 (고유값 관점): `구형 점군은 모든 방향으로 분산이 균일하여 고유값들의 크기가 서로 비슷해지므로, 주축의 방향을 유일하게 정의할 수 없어 불안정해집니다.`

## 4. 현재 구현의 한계

- 자세 추정: `대응점(Correspondence)이 완벽히 알려진 이상적인 조건에서만 Kabsch 알고리즘이 정확하게 동작하며, 완전한 대칭 물체의 경우 PCA 축의 부호 모호성(Ambiguity)이 존재합니다.`
- 궤적 생성: `로봇 팔의 기구학적 한계(Joint Limit)나 장애물 회피, 관절 속도·가속도의 물리적 제한 조건을 실시간으로 반영하지 못합니다.`
- 파이프라인: `단일 관절 및 단순화된 3차원 점군 모델을 가정하고 있으며, 실제 센서의 캘리브레이션 오차나 시간 지연(Latency)을 고려하지 않았습니다.`
- 시연: `오픈 소스 3D 플롯 기반의 시각화이므로 실제 물리 엔진(PyBullet, Gazebo 등) 환경에서의 다물체 동역학 반응을 완벽히 모사하지 못합니다.`

## 5. 개선한다면 무엇을 어떻게

- `ICP(Iterative Closest Point) 알고리즘 도입` -> `대응점이 없는 실제 스캔 점군 데이터에서도 정밀한 자세 정합이 가능하도록 두 점군 간의 거리를 반복적으로 최소화`
- `RANSAC 기반 평면 및 특징점 추출` -> `센서 노이즈나 아웃라이어가 심한 환경에서도 강건하게(Robust) 물체의 유효 영역을 분할`
- `최소 저크(Minimum Jerk) 궤적 최적화` -> `로봇 모터의 기계적 충격과 진동을 최소화하도록 가속도의 변화율까지 부드럽게 제어`
- `실시간 충격 및 관절 한계 검증` -> `궤적 생성 단계에서 역기구학(IK)과 충돌 검사 라이브러리를 연동하여 안전성 확보`
- 개선 효과를 어떻게 측정할 것인지: `실제 로봇 시뮬레이터 환경에서 궤적 추종 오차(Tracking Error) 및 모터 토크 스파이크 발생 빈도를 비교 측정`
